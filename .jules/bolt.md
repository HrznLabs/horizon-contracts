## 2024-07-15 - Redundant SLOADs in Storage Pointer Struct Access
**Learning:** In Solidity 0.8.24 via-IR, accessing multiple fields of a struct through a `storage` pointer does not automatically cache the read values in the EVM stack/memory. If a field (like `dispute.outcome`) is accessed multiple times within the same function scope (e.g., in a sequential `if/else if` chain), the compiler emits a separate `SLOAD` for each access.
**Action:** When a struct field is read multiple times via a storage pointer, manually cache the field into a local stack variable before the first read to eliminate redundant `SLOAD` operations and save gas.
